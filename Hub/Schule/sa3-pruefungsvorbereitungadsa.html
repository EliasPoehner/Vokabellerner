🔌 Protokolle & Ports
📡 SMTP, IMAP, SSL/TLS – auf einen Blick ▼
Protokoll Dienst Port Beschreibung
SMTP Postfix 25 / 587 Simple Mail Transfer Protocol – E-Mail versenden
IMAP Dovecot 143 / 993 Internet Message Access Protocol – E-Mail abrufen & verwalten
SSL Beide – Secure Socket Layer – alt, verschlüsselte Verbindung (public/private Key)
TLS Beide – Transport Layer Security – neu/moderner, funktioniert ebenfalls mit public/private Keys
💡

tls_security_level = may bedeutet: Verschlüsselung kann genutzt werden, ist aber nicht zwingend. Bei must wäre sie verpflichtend. Wir haben plaintext verwendet.

⚙️ Dovecot – Konfiguration
📂 Wichtige Konfig-Dateien unter /etc/dovecot/conf.d/ ▼
Datei10-auth.conf
AAuthentifizierungs-Einstellungen. Wichtigste Zeile: disable_plaintext_auth = no (Plaintext erlauben). Bei yes (Standard) werden SSL/TLS-Schlüssel benötigt – ohne Verschlüsselung würde die Anmeldung verweigert.
Datei10-mail.conf
APfad zur Inbox des Benutzers. Wichtige Zeile: mail_location = maildir:/var/mail/%u – gibt an, wo die E-Mails gespeichert werden. (%u = vollständiger Benutzername)
Datei10-ssl.conf
ASSL/TLS-Konfiguration: Pfade zu ssl_cert (Zertifikat / öffentlich) und ssl_key (privater Schlüssel) sowie das verwendete Verschlüsselungsverfahren.
# Weg zu den Konfig-Dateien
cd /etc/dovecot/conf.d
nano 10-auth.conf   # → disable_plaintext_auth = no
nano 10-mail.conf   # → mail_location = maildir:/var/mail/%u
nano 10-ssl.conf    # → ssl_cert/ssl_key Pfade
⚙️ Postfix – Konfiguration
📄 /etc/postfix/main.cf – Wichtige Einstellungen ▼
🛠️

Konfiguration wird meist über dpkg-reconfigure postfix eingerichtet (graue Menü-Fenster, schrittweise Eingabe). Kann auch direkt in main.cf geändert werden.

# Wichtige Zeilen in /etc/postfix/main.cf

inet_protocols        = ipv4
mynetworks            = 10.5.252.0/24      # vertrauenswürdige Netze (gegen Spam!)
myorigin              = mx.nachname-plattling.de  # Name des Mailservers
mydestination         = mx-lweikl-plattling.de    # Domains, für die dieser Server zuständig ist
smtpd_tls_security_level  = may              # TLS optional (nicht erzwungen)
smtp_tls_security_level   = may
Parameter Bedeutung
mynetworks Vertrauenswürdige Netzwerke – nur diese dürfen den Mailserver als Relay nutzen (Spam-Schutz!)
mydestination Domains, für die dieser Mailserver zuständig ist – E-Mails an diese Adressen werden lokal zugestellt
myorigin Name/Hostname des Mailservers – erscheint im „From"-Header
tls_security_level = may TLS kann genutzt werden, ist aber nicht Pflicht
🌐 DNS & MX-Records
🔍 Wie findet der Mailserver den Empfänger? – nslookup & MX ▼
FrageWie findet Postfix den Mailserver des Empfängers?
AÜber das DNS-System (verteiltes System). Postfix fragt: „Wer ist der Mail-Exchanger für diese Domain?". Der eigene DNS fragt rekursiv weiter, bis eine Antwort kommt.
BefehlWie fragt man per Kommandozeile nach dem MX-Eintrag?
Anslookup -type=MX dachs-plattling.de
nslookup -type=MX weikl-plattling.de

# Beispiel-Antwort:
Server:    127.0.0.1
Address:   127.0.0.1#53

weikl-plattling.de  mail exchanger = 5  mx.weikl-plattling.de.
weikl-plattling.de  mail exchanger = 10 mail.weikl-plattling.de.
# Niedrigere Zahl = höhere Priorität!
Niedrigere MX-Zahl = höhere Priorität DNS läuft auf Port 53 ARP = Address Resolution Protocol
📡

ARP (Address Resolution Protocol): Fragt ins Netz „Wer hat die MAC-Adresse zur IP 10.5.252.5?" → Antwort enthält die MAC. Sichtbar machen mit: arp -a (ARP-Cache anzeigen)

🔥 IPTables – Firewall
📖 Grundprinzip & wichtige Konzepte ▼
WasWas ist IPTables?
AEin IP-Filter / Firewall unter Linux. Erlaubt und sperrt Protokolle und Dienste von/zu einzelnen Rechnern.
⚠️Was ist das wichtigste Prinzip bei IPTables-Regeln?
AReihenfolge ist entscheidend! Die Regeln werden von oben nach unten abgearbeitet – die erste passende Regel gewinnt. Steht ganz unten ein „Erlaube alles", zählen spezifische Regeln darüber nicht mehr.
PrüfungWie fragt die Lehrerin in der Prüfung?
ASie gibt einen Befehl vor und ihr müsst ihn mit den richtigen Parametern bestücken oder die richtige Reihenfolge von Regeln bestimmen. Die exakte Syntax muss bekannt sein!
⚠️

Reihenfolge-Beispiel: Eine Regel „IP sperren" muss vor der Regel „Web erlauben" in der Chain stehen. Sonst greift die Web-Erlaubnis zuerst und die IP-Sperre hat keine Wirkung.

📡 tcpdump – Netzwerk-Traffic beobachten ▼ 
# Beobachte Traffic auf Interface enp0s8 von/zu Host 10.5.252.15
tcpdump -i enp0s8 host 10.5.252.15

# Port 80  = unverschlüsselt (HTTP)
# Port 443 = verschlüsselt  (HTTPS)
# → 3-Wege-Handshake sichtbar (SYN / SYN-ACK / ACK)
Port 80 = HTTP (unverschlüsselt) Port 443 = HTTPS (verschlüsselt) 3-Wege-Handshake: SYN → SYN-ACK → ACK
🦑 Squid – Forward Proxy
📖 Grundlagen & 3 Aufgaben des Forward-Proxys ▼
WasWas ist Squid und welcher Typ ist es?
ASquid ist der Forward-Proxy unter Linux (kein Reverse Proxy). Läuft auf Schicht 7 (Anwendungsschicht).
1️⃣ Caching
  • Speichert statische Web-Inhalte zwischen
  • Bedient Anfragen schneller aus dem Cache
  • Beispiel: oft aufgerufene KFZ-Kleinteile in der Automobilbranche
2️⃣ Eine IP für alle
  • Nur eine IP nach außen für das gesamte Netz
  • Proxy = Stellvertreter – besorgt Seiten im Namen der Clients
  • Empfängt Antworten und verteilt sie intern
3️⃣ Zugriffskontrolle (ACL)
  • Bestimmt, welche Seiten erlaubt oder gesperrt sind
  • Regeln über ACL-Listen in der squid.conf
  • Reihenfolge der Regeln ist entscheidend!
📄 squid.conf – Konfiguration & Setup ▼ 
# Konfigurationsdatei ist sehr groß (fast ein Handbuch)
# → nur aktive Zeilen anzeigen:
cat squid.conf | grep -v "^#" | grep -v "^$"

# Sicherungskopie anlegen (IMMER zuerst!):
cp squid.conf squid.conf.orig

# Bereinigte Version als neue Config:
cat squid.conf | grep -v "^#" | grep -v "^$" > squid2.conf
cp squid2.conf squid.conf
📋 Squid ACL – Syntax & Regeln
⚖️ ACL-Typen & Syntax ▼
ACL-Typ Beschreibung Beispiel
src Quell-IP oder Netz acl tobias src 10.11.111.7
url_regex URL-Muster (regulärer Ausdruck, case-insensitive mit -i) acl shopping url_regex -i amazon ebay
dstdomain Ziel-Domain acl social dstdomain facebook.com
port Ziel-Port acl SSL_ports port 443 
# Beispiel aus der Stunde:
acl shopping url_regex -i amazon ebay   # Shopping-Seiten
acl tobias src 10.11.111.7              # Tobias' Rechner

# → Regeln (Reihenfolge entscheidend!):
http_access deny tobias                  # Tobias blockieren
http_access deny shopping               # Shopping-Seiten sperren
http_access allow localnet              # Rest erlauben
⚠️

Syntax muss sitzen! Die Lehrerin gibt die Struktur vor – ihr müsst die richtigen ACL-Namen, Typen und http_access-Regeln eintragen. Die Reihenfolge (deny vor allow) ist der häufigste Fehler!

🔄 Reihenfolgen-Prinzip – Vergleich IPTables vs. Squid ACL ▼
🔥 IPTables
  • Regeln werden von oben nach unten verarbeitet
  • Erste passende Regel greift
  • Spezifisches vor Allgemeinem
  • IP-Sperren vor globalen Erlaubnissen
🦑 Squid ACL
  • Regeln werden von oben nach unten verarbeitet
  • Erste passende http_access-Regel greift
  • deny vor allow für Sperren
  • ACL-Definition ≠ Regel – erst http_access wirkt!
